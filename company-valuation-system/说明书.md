# 说明书

这份文档写给拿到这个文件夹的人，从装环境到读结果一路走完，也交代这套东西能证明什么、证明不了什么。下面每一条命令和每一个数字都来自交付前在全新临时目录里的真实运行，快照日 2026-10-12，财务报告期 20260630。系统是研究方法论原型，不构成投资建议。

## 这是什么

它把"一家公司值多少钱、现价跟这个值错开多少"做成一套能跑、能复现、能证伪的流程，先诚实判断能不能判，再谈贵贱。

判断谁贵谁便宜，本身不是一个能证伪的命题，换一套估值假设结论就能翻转。所以这套东西不卖结论，卖流程，只做三件事：先度量，用不依赖单一模型的错配指标，把贵和便宜变成可比的横截面数字；再检验，用横截面秩相关、五分组组合、扣掉交易成本，看这个度量对未来收益有没有预测力；最后裁决，在交易成本和多重检验校正下判断预测力是真信号还是数据挖掘，达不到门槛就如实记 undetermined。

它不做的事同样清楚：不预测点位，不推荐买卖，不承诺收益。当前真实结论就是 undetermined，这不是失败，是诚实裁决，原因写在后面的局限一节。

## 目录与分层

代码分三层，边界很清楚。`core/` 只接收内存数据，负责所有算法，不碰文件也不碰数据库；`dataio/` 是唯一读写数据库的地方，向 `core/` 吐 dict 和 numpy 数组；文档、示例、看板单独一层；根目录只放很薄的入口脚本，做参数解析然后调下层。依赖方向单向，`core/` 不 import `dataio/`，没有循环导入。

```
company-value-system-final-2026-10-12/
├─ core/          算法层：stats / valuation / quality / testing / percentile / report
├─ dataio/        数据接口层：paths、astock、schema.md、example_adapter.py
├─ docs/          研究方案、数据边界、安装与使用说明、优化报告、诊断记录、BUG 报告
├─ examples/      demo.py 与脱敏样例数据
├─ board/         看板生成脚本、生成好的 HTML、GH Pages 说明
├─ mispricing_screener_v2.py     主入口：多法内在价值 + 错配 + 检验 + 历史分位
├─ quality_value_screener_v2.py  质量 + 估值双因子排序
├─ valuation_percentile.py       自身历史估值分位
├─ demo.py                       薄壳，转调 examples/demo.py
└─ README.md / README.en.md / requirements.txt / LICENSE
```

想接自己的数据，改 `dataio/astock.py` 里对应函数的 SQL。字段和单位一致的话零改动，直接用 `--db` 指过去就行，具体看 `dataio/schema.md` 最后一节。

## 安装

这是一个普通的 Python 项目，不是要装进系统的软件，clone 或解压到任意文件夹都可以，唯一的依赖是 numpy。Python 需要 3.10 以上，我们在 3.12.10 上实测过。`python`、`python3`、`py -3.12` 三种写法等价，按系统选一个，Windows 一般用 `py -3.12` 或 `python`，macOS 和 Linux 用 `python3`。

```bash
python -m pip install -r requirements.txt
python -c "import numpy; print(numpy.__version__)"
```

`requirements.txt` 里只有一行 numpy，其余全是标准库，包括 sqlite3、argparse、math、os、csv、collections，不用 pandas、scipy、sklearn。想隔离环境可以建虚拟环境，Windows 上用 `py -3.12 -m venv .venv` 之后直接调 `.venv\Scripts\python.exe`，省得激活；macOS 和 Linux 改用 `.venv/bin/python`。装完先跑下面的 demo 验证，再往下走。

## 数据

需要两类 SQLite 库，一律只读打开，不会写坏你的库。`astock.db` 是 A 股主库，放日 K 前复权收盘、财务含 pub_date、估值快照、行业和股本，三个脚本都要用；`valuation_hist.db` 放逐日历史估值序列，估值模式的历史分位段和 `valuation_percentile.py` 用它。字段和单位约定在 `dataio/schema.md`。

容易踩的地方有三个：`fin_report.revenue` 和 `net_profit` 单位是元，`valuation_daily.total_mv` 和 `circ_mv` 单位是万元，`float_share_hist.total_shares` 单位是股。脚本已经按这个换算过了。

脚本按固定顺序找库，最稳的是显式指定。先看命令行 `--db`，再看环境变量 `ASTOCK_DB`，再看仓库相对位置 `data/astock.db`，最后看平级相对位置 `../../astock-site/data/astock.db`，也就是历史遗留的那个便利候选，别人拿到仓库通常不命中。历史估值库用 `--hist-db` 指定，不指定时找仓库根或 `data/` 下的 `valuation_hist.db`。代码里没有写死本机绝对路径，不传 `--db` 又找不到库的时候，脚本会打印清晰的提示并给出几种做法，然后以退出码 2 结束，不会抛一堆栈。

`*.db`、大 `*.csv`、`*_out.txt` 都在 `.gitignore` 里，仓库只带一份脱敏小样例 `examples/data/sample_valuation_snapshot.csv`，用来演示列结构，不是真实行情。要跑全市场必须自备数据，可以从 akshare、东方财富、新浪、腾讯这些公开源采集后按上面字段落库。

## 怎么跑

先跑 demo，它不需要数据库，读 `examples/data/sample_valuation_snapshot.csv`，打印十只样例的排序表，最后输出 `DEMO OK ✔`，Windows 默认的 GBK 控制台会自动把 ✔ 降级成 √，属正常。看到这行，环境就装好了，退出码是 0。

```bash
python demo.py
```

主入口跑全市场盘点：

```bash
python mispricing_screener_v2.py --mode both --db <DB> --hist-db <HIST> --out v2_out.txt
```

只看榜单用 `--mode value`，只看检验用 `--mode test`。本次实测会写出一份文本，里面有估值的便宜榜、贵榜、低盈利质量单列、饱和检查、自身历史分位，还有检验表。本次运行参与 4171 只，进主榜 3732 只，单列低盈利质量 439 只，历史分位覆盖 3592 只；检验部分有效交易日 276，Bonferroni 临界 t 值约 2.87。

看单只票或几只票，用 `--codes`：

```bash
python mispricing_screener_v2.py --mode value --db <DB> --hist-db <HIST> --codes 600519,000858 --out one.txt
```

它只过滤显示，行业和全市场分位、错配秩仍按全池算，所以单票看到的贵不贵，是在全市场坐标系里的位置。

质量加估值排序跑这条，加 `--val-neutral` 会让估值分在行业内部再排一次，压住整张榜变成押注某个便宜板块的倾向：

```bash
python quality_value_screener_v2.py --mode both --db <DB> --top 40 --watchlist watchlist.csv --out qv_out.txt
```

本次实测参与打分 5278 只，过质量关 2639 只，另外写出的清单是纯文本行，不含大数据。自身历史估值分位跑 `valuation_percentile.py --hist-db <HIST> --min-days 250 --lookback 750 --top 25 --out pct_out.txt`，本次实测库内 5371 只、9117468 行，历史满 250 天的有 5202 只。

看板用 `board/make_board.py --db <DB> --out board/valuation_board.html` 生成，大约一分钟，加 `--hist-db` 会追一节自身历史分位，加 `--no-test` 可以跳过检验省时间。生成出来的 HTML 是单文件、数据内嵌、零外链，双击用浏览器打开就行，不装 Python、不连库、不联网，也可以直接发微信或邮件给别人。仓库里那份样品内嵌的是快照日 2026-10-12 的数据，头部标着评分池 5278 只、过质量关 2639 只、质量关阈值 50.0、错配度样本 3598 只。

## 输出怎么读

估值模式的主表里，`price` 是快照日收盘价，`eps_ann` 是年化 EPS，取 `pub_date` 不晚于快照日的最近一期，按报告期年化，一季报乘 4、半年报乘 2、三季报乘 4/3、年报乘 1。`IV_A` 是行业 PE 中位数乘年化 EPS，`IV_B` 是年化 EPS 除以折现率（默认 8%，零增长 DCF 的特例），`IV_C` 是行业 PB 中位数乘每股净资产，缺净资产时显示 NA。`mispr` 是错配度，等于 `mean(pctrank(log(price/IV)))`，取值 0 到 100，大于 50 偏贵、小于 50 偏便宜，它衡量的不是价差本身，而是价差在全池里的秩百分位。低盈利质量清单单独列 E/P 低于 `--earn-floor`（默认 0.5%）的票，不进主榜，这是为了防止微利股的 EPS 趋近零、把内在价值拉垮、错配炸榜。饱和检查列出主榜最贵 15 只去重后的 mispr 值，v1 会全部并列成同一个数，v2 应该是连续不同的百分位。自身历史分位那段给出 PE 当前值、PE 在自身历史里的分位（越大越贵）、便宜度等于各分位反向均值（大于 50 偏便宜）、参与计算的交易日数。

检验模式的表里，`proxy` 是因子，有真估值因子 `E/P(pit价值)`、21 日反转 `rev21`、偏离 120 日均线 `dev120`；`h` 是持有期，单位交易日，取 21、63、126、252。`IC_mean` 是各再平衡日秩相关系数的均值，`IC_t` 是它的 t 值，`IC95%CI` 是自举 2000 次得到的 95% 区间，跨 0 就是不显著。`Q5-Q1净` 是最便宜组减最贵组的平均收益，已经扣掉往返成本（默认 0.30%）。`alpha` 是这组价差对市场因子回归后的截距，接近 0 说明价差多半只是市场 beta。`n` 是独立再平衡样本数，持有期越长、历史越短，n 越小。表头的 Bonferroni 临界把门槛按代理数乘期限数收紧，本次 N 等于 12，临界约 2.87。

undetermined 的意思是用现有数据判不了。判定线要求独立样本足够多、扣费后置信区间下界大于零，两条都满足才写有效。特别要当心 n 很小的高 IC，比如 n 等于 3 却有 0.25 的 IC，那只是样本太少，不可信。

质量与估值排序里，`Q` 是质量分，池内百分位 0 到 100；`V` 是估值分，池内百分位；`comp` 是综合分，等于 0.5 乘质量分的 z 值加 0.5 乘估值分的 z 值，只在通过了质量关的池内计算并百分位化；`qN` 和 `vN` 是实际参与计算的质量和估值成分个数，缺项越多越小，越该谨慎。清单文件里还有 roe、gross_margin、net_margin、rev_yoy、net_yoy、eps、book_yield、sales_yield。历史分位那份输出给出 PE、PB、PS 当前值，以及它们各自在自身历史里的分位（越大越贵）和反向的便宜度。

## 局限与边界

当前结论是 undetermined，不是有效。

历史太短是最硬的约束。全市场完整日 K 实测只有 276 个交易日，从 2025-08-19 到 2026-10-12。12 个月期限的非重叠样本基本为零，本次实测里 rev21 和 dev120 在 252 日持有期下 n 为 0，E/P 为 1 且 t 值不可计算。所以置信区间必然很宽，多数组合达不到有效的门槛。更早的 `kline_daily_hist` 只是部分票池，不能当全市场用。

估值历史同样有限。`valuation_daily` 实测只有 4 个交易日，2026-09-30、10-02、10-09、10-12，所以那个口径下的 PE、PB 历史分位不可用，这是最大的缺口。交付的 `valuation_hist.db` 覆盖 2018 年以来的逐日序列，可以支撑自身历史分位，但长周期横截面检验仍然受日 K 长度限制。

绝对估值的输入缺得比较多。没有账面价值、现金流、股利、负债，标准 DCF、RIM、DDM 都没法诚实实现，原型只能用盈利资本化做代理，假设很强，结论只能定性参考。book_yield 里的净资产是用净利除以 ROE 反推的近似值，roe 没区分加权还是摊薄，net_profit 没区分归母还是全部，只能当量级参考。

微利股的极值已经用对数缺口、秩合成和盈利质量闸处理过，但榜单仍然对阈值敏感，不能直接当名单用。EPS 年化按报告期推断，忽略了季节性和季度波动。成本模型用固定的 0.30% 往返，没有建模涨跌停的不可成交比例和冲击成本。质量六维里现金流、资本配置、财务稳健这些项大多没有对应字段，只能用可得代理近似，质量分实际只有 roe、gross_margin、net_margin、rev_yoy、net_yoy 五个成分。分析师预期、融券成本和券源、股利明细在本地都缺，也没有伪造。

口径会漂移，这一点要特别注意。上游库一直在更新，快照天数和财务期数都在变，结论不能跨日直接比较，每次复算都该重新记下快照日和财务期。这也是本说明书里示例数字没法逐字复现的原因，见最后一节。看板那份 HTML 内嵌的是生成当日 2026-10-12 的快照，打开它看到的是那天，不是当前行情。

## 交付自检

交付前，我们在一个全新临时目录里模拟了陌生人拿到这个项目的过程：复制、建 venv、装依赖、跑 demo、跑主入口，另外用无头浏览器打开看板核对渲染。

先记已经修掉的。demo.py 会在 Windows 默认的 GBK 控制台上崩掉，因为 `DEMO OK ✔` 里的 ✔ 不在 GBK 字符集里，会抛 UnicodeEncodeError，退出码 1，这是开箱即跑的硬伤。现在完成标记会按控制台编码自动降级，UTF-8 下是 ✔、GBK 下是 √，同时三个入口脚本和 `board/make_board.py` 都加了 stdout 的 errors 守卫，报告文本里的减号字符在 GBK 控制台同样会触发崩溃，一并处理了，文件输出仍然是 UTF-8。修复后在临时目录里复测，输出 DEMO OK √，退出码 0。

再记站得住的。看板 HTML 零外链，没有任何 http 或 https，也没有外部 src 和 href，无头浏览器渲染有数据，顶部榜单、四象限散点、错配直方图都正常出图，头部写的评分池 5278、过质量关 2639 和命令输出一致，中文正常。命令不给库的时候打印友好提示并返回退出码 2，不抛脏栈，给真库能跑。代码里没有本机绝对路径残留。样例数据在文档里始终标注为脱敏假数据，没有冒充真数据。三法内在价值、时点重建、自举加 Bonferroni、undetermined 判定线都和代码实现一致。

最后是不敢担保的。任何收益或选股有效性，当前结论就是 undetermined；示例数字跨日或跨机器可复现，底层库在漂移；book_yield 和每股净资产近似口径的精度，以及 0.30% 成本模型是否贴近真实；仓库 clone 到任意位置后能否自动找到数据库，稳妥做法是显式用 `--db`；看板样品反映当下行情，它只是生成日的快照。
