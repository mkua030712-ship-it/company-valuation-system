# 使用说明

这份文档面向没接触过这套系统的人，照着它就能装好环境、喂数据、跑出结果并看懂结果。里面的命令和输出都来自真实运行，示例日期是 2026-10-12，估值快照日同一天，财务报告期 20260630。方法论和局限不在这里展开，见 `README.md` 和 `docs/` 里的其他几篇。

## 脚本构成

系统有三个入口脚本，各管一段。`mispricing_screener_v2.py` 是主入口，判定一家或一批公司值不值，做多法内在价值、错配、时点检验和自身历史分位，用 `--mode value/test/both` 切换。`quality_value_screener_v2.py` 看公司好不好，做质量分、估值分和综合分排序，含行业中性，用 `--mode rank/diag/both`。`valuation_percentile.py` 看现在在自身历史里贵不贵，算逐日历史 PE、PB、PS 分位，直接跑即可。

| 脚本 | 作用 | 主命令 |
|---|---|---|
| `mispricing_screener_v2.py` | 主入口：多法内在价值 + 错配 + 时点检验 + 自身历史分位 | `--mode value/test/both` |
| `quality_value_screener_v2.py` | 质量分 + 估值分 + 综合分排序（含行业中性） | `--mode rank/diag/both` |
| `valuation_percentile.py` | 逐日历史 PE/PB/PS 分位 | 直接跑 |

## 环境与数据

环境只需要 Python 和 numpy。Python 用 3.12 实测（本机以 `py -3.12` 调起，3.9 以上大概率也行，没逐一验证），依赖只有 `numpy`，其余是标准库，包括 `sqlite3`、`argparse`、`math`、`os`、`csv`、`collections`，刻意不用 pandas、scipy、sklearn。

```powershell
py -3.12 --version
py -3.12 -m pip install -r requirements.txt
py -3.12 -c "import numpy; print(numpy.__version__)"
```

数据方面需要两个 SQLite 库，都是只读使用。`astock.db` 是 A 股主库，放行情、财务、估值快照、行业和股本，三个脚本都要用；`valuation_hist.db` 放个股自身的历史 PE、PB、PS 序列，估值模式的历史分位段和 `valuation_percentile.py` 用它。

脚本按固定顺序找库，最稳的是显式指定：命令行 `--db`，环境变量 `ASTOCK_DB`，仓库相对位置 `data/astock.db`，平级相对位置 `../../astock-site/data/astock.db`。历史估值库用 `--hist-db` 指定，默认取脚本同目录下的 `valuation_hist.db`。本仓库不含数据库，`*.db` 和大 `*.csv` 都已 gitignore，要跑得先有一份符合下面表结构的库。

| 库 | 作用 | 谁需要它 |
|---|---|---|
| `astock.db` | 行情 / 财务 / 估值快照 / 行业 / 股本 | 三个脚本都要 |
| `valuation_hist.db` | 个股自身历史 PE/PB/PS 序列 | 估值模式的历史分位段、`valuation_percentile.py` |

脚本实际用到的表和字段如下，字段结构和单位也见 `dataio/schema.md`，列名示例见 `examples/data/sample_valuation_snapshot.csv`（脱敏手造，非真实行情）。`kline_daily` 用 `code, date, close, adjust`，只用 `adjust='qfq'` 前复权，有效交易日按当天行数不少于 3000 判定，用来剔除休市日和残缺日，阈值可用 `--min-rows-per-day` 调。`valuation_daily` 用 `date, code, name, industry, price, pe, total_mv, circ_mv`，`price` 单位元，`total_mv` 和 `circ_mv` 单位万元，`pe` 可以为负或空。`fin_report` 用 `period, code, name, industry, eps, revenue, rev_yoy, net_profit, net_yoy, roe, gross_margin, pub_date`，`revenue` 和 `net_profit` 单位元，`pub_date` 用于时点，避免前视。`float_share_hist` 用 `code, change_date, total_shares, float_shares`，单位是股。`stock_industry` 用 `code, name, industry`，做行业兜底。历史估值库里是 `valuation_hist`，字段有 `code, date, close, pe_ttm, pe_static, pb, ps, pcf, total_mv, circ_mv, total_shares, float_shares`。

没有数据的话，数据可以从 akshare、东方财富、新浪、腾讯这些公开源采集，按上面的字段落库。落库之后不用改脚本，用 `--db` 指过去即可。字段名或单位和上面不同，就改脚本里对应的 `SELECT`，或者做一层视图映射。

## 命令

下面 `<DB>` 指 `astock.db` 路径，`<HIST>` 指 `valuation_hist.db` 路径。跑全市场盘点：

```powershell
py -3.12 mispricing_screener_v2.py --mode both --db <DB> --hist-db <HIST> --out v2_out.txt
```

输出 `v2_out.txt` 是 UTF-8 文本，估值段有最便宜和最贵榜、低盈利质量单列、饱和检查、自身历史分位，检验段有 `E/P(pit价值)`、`rev21`、`dev120` 乘四个期限的 IC、t 值、自举区间、净收益和 alpha。只要榜单用 `--mode value`，只要检验用 `--mode test`。

看单只票或几只票：

```powershell
py -3.12 mispricing_screener_v2.py --mode value --db <DB> --hist-db <HIST> --codes 600519,000858 --out one.txt
```

`--codes` 只过滤显示，行业和全市场分位、错配秩仍按全池计算，所以单票的贵不贵仍是全市场坐标系里的位置，输出只列这几只票的 price、IV_A、IV_B、IV_C、mispr 和它们的 PE 历史分位。

质量加估值排序：

```powershell
py -3.12 quality_value_screener_v2.py --mode both --db <DB> --top 40 --watchlist watchlist.csv --out qv_out.txt
```

输出 `qv_out.txt` 里是榜单加诊断分布、相关和前瞻检验，另外写 `watchlist.csv`，是通过质量关的清单，纯文本行，不含大数据。加 `--val-neutral` 会让估值分在行业内再排一次，避免整张榜变成押注便宜板块；指定池可以用 `--universe industry --industry 白酒Ⅱ`，也可以用 `--codes`。

历史估值分位：

```powershell
py -3.12 valuation_percentile.py --hist-db <HIST> --min-days 250 --lookback 750 --top 25 --out pct_out.txt
```

输出 `pct_out.txt`，最便宜和最贵各 25 只，带 PE、PB、PS 分位和便宜度。

## 输出怎么读

估值模式主表里，`price` 是快照日收盘价，`eps_ann` 是年化 EPS，取 `pub_date` 不晚于快照日的最近一期，按报告期年化。`IV_A` 是行业 PE 中位数乘年化 EPS，`IV_B` 是年化 EPS 除以折现率（默认 8%，零增长 DCF 的特例），`IV_C` 是行业 PB 中位数乘每股净资产，缺 BVPS 时显示 NA。`mispr` 是错配度，等于 `mean(pctrank(log(price/IV)))`，取值 0 到 100，大于 50 偏贵、小于 50 偏便宜，它不是价差本身，而是价差在全池里的秩百分位。

| 列 | 含义 |
|---|---|
| `code / name / industry` | 代码 / 名称 / 行业 |
| `price` | 快照日收盘价（元） |
| `eps_ann` | 年化 EPS（一季 ×4 / 半年 ×2 / 三季 ×4/3 / 年报 ×1） |
| `IV_A` | 行业 PE 中位数 × 年化 EPS |
| `IV_B` | 年化 EPS / r（零增长 DCF 特例，默认 8%） |
| `IV_C` | 行业 PB 中位数 × 每股净资产（缺则 NA） |
| `mispr` | 错配度，池内秩百分位，>50 偏贵、<50 偏便宜 |

低盈利质量清单把 `E/P%` 低于 `--earn-floor`（默认 0.5%）的票单列出来，不进主榜，目的是防止微利股的 EPS 趋近零、把内在价值拉垮、错配炸榜。饱和检查列出主榜最贵 15 只的 mispr 去重值，v1 会全部并列成同一个数，v2 应该是连续不同的百分位。自身历史分位那段给出 PE 当前值、PE 在自身历史里的分位（0 到 100，越大越贵）、便宜度等于各分位反向均值（大于 50 偏便宜），以及参与计算的交易日数。

检验模式的列如下。判断的简易标准是 IC 方向与预期一致（E/P 预期正 IC，rev21 和 dev120 预期负 IC），并且 t 值超过 Bonferroni 临界、自举区间不跨 0，才勉强算值得继续观察，否则一律记 undetermined。

| 列 | 含义 |
|---|---|
| `proxy` | 因子：`E/P(pit价值)` / `rev21` / `dev120` |
| `h` | 持有期（交易日）：21 / 63 / 126 / 252 |
| `IC_mean` | 各再平衡日 Spearman 秩相关的均值 |
| `IC_t` | IC 的 t 值，|t| 越大越显著 |
| `IC95%CI` | IC 序列 2000 次自举的 95% 区间，跨 0 即不显著 |
| `Q5-Q1净` | 最便宜组减最贵组的平均收益，已扣往返成本（默认 0.30%） |
| `alpha` | 价差对市场因子回归的截距，≈0 说明价差多半只是市场 beta |
| `a_t` | alpha 的 t 值 |
| `n` | 独立再平衡样本数，h 越大、历史越短，n 越小 |
| `Bonferroni |t| 临界` | 按 `N = 代理数×期限数` 收紧后的 |t| 临界 |

质量与估值排序的列里，`Q` 是质量分（池内百分位 0 到 100），`V` 是估值分，`mispr` 是错配，`comp` 是综合分（等于 0.5 乘 z(Q) 加 0.5 乘 z(V)，只在过质量关的池内算），`qN` 和 `vN` 是实际参与质量、估值计算的成分个数，缺项越多越小。`watchlist.csv` 里另有 `roe`、`gross_margin`、`net_margin`、`rev_yoy`、`net_yoy`、`eps`、`book_yield`、`sales_yield`。历史分位那份输出给出 PE、PB 当前值和各自的分位，以及反向的便宜度。

## 实跑示例

先看单只票。跑茅台加五粮液：

```powershell
py -3.12 mispricing_screener_v2.py --mode value --codes 600519,000858 --hist-db <HIST> --out one.txt
```

2026-10-12 那次的输出节选如下（这份数字只属于那一天，底层库会漂移）：

```text
## 模式 value (v2) — 多法内在价值与秩合成错配

- 估值快照日：2026-10-12；财务时点：20260630（EPS 年化 ×2，r=8%，E/P 闸=0.50%）
- 参与：4015 只；进主榜（盈利质量达标）：3624 只；单列低盈利质量：391 只
- 单票过滤：仅显示 000858、600519（行业/全市场分位、错配秩仍按全池计算）

### 最便宜（mispr_rank 最小）（前 12）
code     name     industry      price  eps_ann       IV_A       IV_B       IV_C    mispr
000858   五 粮 液    白酒Ⅱ           71.06     4.51      90.42      56.38      61.61     39.0
600519   贵州茅台     白酒Ⅱ         1288.00    71.14    1426.25     889.25     414.73     53.8

### 自身历史估值分位（真实纵向分位；覆盖 2 只，历史数据回补中）
code     name     industry         PE      PE分位      便宜度     天数
600519   贵州茅台     白酒Ⅱ           19.62       7.6     92.9    750
000858   五 粮 液    白酒Ⅱ           30.80      53.6     73.6    750
```

读法是，茅台 mispr 53.8，略偏贵一侧，五粮液 mispr 39.0，偏便宜一侧，两者都只是全池秩百分位，不代表该买或该卖。纵向看更有意思，茅台当时的 PE 处在自身历史 7.6% 分位，很便宜，五粮液在 53.6%，中位附近，所以茅台是横向略贵、纵向很便宜，五粮液是横向偏便宜、纵向中位。

再看全市场检验的一部分：

```text
Bonferroni（N=12，α=0.05）|t| 临界 ≈ 2.87

proxy            h   IC_mean    IC_t      IC95%CI      Q5-Q1净     alpha      a_t       n
E/P(pit价值)      21    0.0340    0.30 [-0.154,+0.256]      0.0073   -0.0207    -0.02       5
E/P(pit价值)      63    0.2516    7.57 [+0.195,+0.310]      0.0974    0.0553     0.07       3
rev21           63   -0.0993   -1.99 [-0.194,-0.010]     -0.0381   -0.0351    -0.05       9
dev120          63   -0.1470   -1.46 [-0.319,+0.025]     -0.0244    0.0381     0.02       5
```

E/P 在 63 日那行 IC 0.25、区间不跨 0，看着很强，但 n 只有 3，独立样本太少，不可信，判 undetermined。rev21 在 63 日的 IC 是 −0.10，方向对，但 t 值 1.99 没到 2.87，没过多重检验，只能算继续观察。所有 alpha 都接近 0，说明价差基本是市场 beta，不是真超额收益。

质量加估值排序那次，参与打分 5278 只，剔 ST 之后过质量关 2639 只，榜前几名的 Q 和 V 都是池内百分位，均值天然接近 50，comp 是两者合成后的百分位，mispr 沿用 v1 的 z 合成口径，负值表示便宜。qN 为 4 说明那只票只有 4 个质量成分可得，缺了 1 项，成分越少越该谨慎。

## 常见坑

别拿不同日期的输出直接比，上游库每天都在更新，快照日和财务期都在变，每次复算都要记下这两个日期。`--mode test` 里 n 小于 5 的行基本只能当看看，别信。单票看的是全池坐标，`--codes` 只筛显示，不改分位口径。缺数据就别硬算，没有 BVPS 时 IV_C 是 NA，没有现金流、负债、股利时标准 DCF、RIM、DDM 做不了，系统用了代理，局限见 README。默认参数是 r 等于 0.08、年化按报告期自动、E/P 闸 0.5%、往返成本 0.30%、种子 20261011，都可以用命令行覆盖。三个脚本都以只读方式打开数据库，不会写坏你的库。

本文所有命令和输出都来自本地真实运行，示例日期 2026-10-12。系统是研究方法论原型，不构成投资建议。
